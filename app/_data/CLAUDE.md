# app/_data — content layer

All site content is defined here as static TS and Markdown. There is no CMS and no database.
Every file is imported directly by Server Components and API routes.

## Files and their consumers

| File | Exports | Consumed by |
|---|---|---|
| `projects-data.ts` | `filters` (tech filter groups), `projects` (array of project objects) | `app/projects/page.tsx`, `app/projects/[slug]/page.tsx`, `components/projects/filter-sidebar.tsx`, `app/sitemap.ts`, `app/api/chat/route.ts` |
| `about-data.ts` | `sidebarSections` (about sidebar tree + contacts), `mainContent` (key → `{language, content}`) | `app/about/[[...slug]]/page.tsx`, `components/about/about-sidebar.tsx`, `components/about/about-page-client.tsx`, `app/api/chat/route.ts` |
| `experience-data.ts` | `experiences` (career timeline, newest first; `lane` main/side, git-style `ref`) | `components/home/timeline.tsx`. Duplicates the jobs in `about-data.ts` `experience/*`, so keep both in sync |
| `contact-data.ts` | `contacts`, `findMeAlsoIn` (lucide icon + label + href) | `components/contact/contact-sidebar.tsx` |
| `content/*.md` | Long-form project READMEs (GFM) | Read with `fs` by `app/projects/[slug]/page.tsx` and `app/api/chat/route.ts` |
| `blurhash-data.json` | Map of image path → `{blurhash,width,height}` | **Nothing imports it.** `tools/generate-blurhash.mjs` writes it |
| `about/*.ts` | Old per-section copies of the about content | **Unused.** The live content is inline in `about-data.ts`. Do not edit these expecting a change on the site |

## Projects (`projects-data.ts`)
The shape is `ProjectType` in `app/models/project.ts`. The array is not explicitly typed against it, so keep the fields consistent.
Key fields:
- `slug`: the URL `/projects/<slug>`. It also feeds the sitemap.
- `markdownFilename`: a file name inside `content/`. If the file is missing, the page shows "Project description not found."
- `imageUrl`, `backgroundImage`, `logo`, `gallery[]`: paths under `/optimized/images/*-{small,medium,large}.webp`
  (generated by `tools/optimize-images.mjs`).
- `technologies[]`: `{name, icon (devicon class), version?, description}`. These drive the "Tech Stack" tab and filtering.
- `difficulty`: a **string** "1"–"5", rendered as gem icons. "5" pulses.
- `color`, `tags`, `technicalDetails`, `liveUrl`, `repoUrl` (an empty string hides or disables the button).
- One commented-out entry (id 7, `hr_dataset`) is at the end of the file.

Current projects: `torrent-streamer` (Playpex), `agentic-analytics` (HRizon), `website-builder` (Nexits),
`my_portfolio`, `devops_playground` (Ops-Forge), `elder_care_saas` (EldSync), `kairouan-rose` (freelance, Payload B2B platform).

### Filtering contract
`filters[].technologies[].id` goes into `?tech=id1,id2`. `app/projects/page.tsx` keeps a project when
`project.technologies.some(t => t.name.toLowerCase() === id)`, with OR semantics across the filters.
**When you add a filter, make its `id` exactly equal to the lowercased `name` used in the project technologies.**
Otherwise the filter matches nothing.

### Adding a project
1. Put source images in `public/images/` and run `node tools/optimize-images.mjs`.
2. Add `content/<name>.md`. Images inside it use `/images/...` paths, which `LazyImage` and markdown `img` can route through `/api/images`.
3. Append the object to `projects` with a unique `id` and `slug`.
4. The sitemap and the AI chat context pick it up automatically.

## About (`about-data.ts`)
- `mainContent` keys are route paths relative to `/about/`: `bio`, `interests`, `education/high-school`,
  `education/university`, `experience/nexits`, `experience/talan`, `experience/kairouan-rose`.
- Each value is a **code string**, usually a TS file with a big doc comment. It is shown with syntax highlighting
  in `ContentPanel` using `language`. The voice is first person, written as source code.
- `sidebarSections` items have `path: "/about/<key>"`. The about client derives tab names and icons by matching
  `item.path.replace('/about/','') === key`. **Sidebar paths and `mainContent` keys must stay in sync.**
- Folder items (`/about/experience`, `/about/education`) have no content entry. They are tree nodes only.
- The section with `isContact: true` renders `label`/`href` links instead of routes.

## AI chat grounding
`app/api/chat/route.ts` builds its system prompt from **all** `mainContent` entries, plus each project's
`longDescription`, its technologies, and the full `content/*.md`. Anything written here is visible to the chatbot,
so do not put private info here. Long markdown also increases the prompt size on every request.
