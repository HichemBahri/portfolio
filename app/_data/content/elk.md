# ELK Log Monitoring

Real-time collection, analysis and monitoring of the web logs of an e-commerce site, with the Elastic stack, a suite of Python analyses and automated alerts, behind a Flask interface built for a marketer, not an engineer.

> **Master's course project** (Big-data systems architecture, IHEC Carthage).

## Objectives

- Collect and structure the Nginx logs generated by an e-commerce site.
- Analyse them in near real time: user journeys, cart abandonment, error patterns.
- Visualise and monitor through Kibana and Python, to support marketing and operations decisions.
- Wrap the whole pipeline in a web interface so it can be triggered and read by a non-technical user.

![The analytics space: Elasticsearch queries, Python analyses and Kibana dashboards from one place](/optimized/images/elk_1-large.webp)

## The pipeline

```
Nginx logs ──► Filebeat (TLS) ──► Logstash (grok · mutate · date · geoip) ──► Elasticsearch ──► Kibana
                                                                                    │
                                                                                    └──► Python analyses + alerts ──► Flask UI
```

**Filebeat** tails the Nginx access and error logs and ships them to Logstash on port 5044 over TLS, with certificates on both sides. It handles log rotation and buffers if Logstash is temporarily down.

**Logstash** is where the work is. A custom Grok pattern extracts IP, timestamp, HTTP status, URL, user agent and the specific technical error messages; `mutate` drops the noise; `date` fixes the timestamp; a **GeoIP** filter turns the IP into a `geo_point`. Parse failures are tagged and routed to a separate index instead of being lost.

**Elasticsearch** receives documents with an explicit mapping on the fields that are queried most (status codes, URLs, IPs, geo points), which keeps the dashboards fast.

## Elasticsearch queries

The first page runs bool queries and aggregations against the index through the Python client and renders the results as KPIs: the most frequent HTTP errors, the problematic IPs, and a refresh button to pull the latest data.

![Most frequent HTTP errors, straight from Elasticsearch aggregations](/optimized/images/elk_6-large.webp)

## Kibana dashboards

Business dashboards built in Kibana over the same index: conversion rate and cart-abandonment rate per week, top pages by unique visitors, errors per request.

![Kibana: conversion rate and abandonment rate per week](/optimized/images/elk_5-large.webp)

## Python analyses

A set of Python scripts query Elasticsearch, build the analyses with pandas and render charts with matplotlib and seaborn: top countries generating errors, distribution of HTTP error codes, errors per day and per hour, suspicious and most frequent user agents. The charts are regenerated on each run and replace the previous ones, so the interface always shows the latest data without going through Kibana.

![Generated analysis charts: GeoIP countries, HTTP errors, errors over time, user agents](/optimized/images/elk_3-large.webp)

Error sources are geolocated with the GeoIP database and plotted on an interactive map.

![GeoIP map of the IPs behind the errors](/optimized/images/elk_4-large.webp)

## Automated alerts

A monitoring job watches the most frequent error types (403, 500, 502, 503, 504) and specific technical errors. When a configured threshold is crossed (for instance 100 HTTP errors in the window), it sends an **e-mail alert** and writes the event to a log file. The job is started and stopped from the interface, which also shows the live surveillance log.

![Launch the analyses, enable the alerts, watch the surveillance log](/optimized/images/elk_2-large.webp)

## Stack

Elasticsearch, Logstash, Kibana, Filebeat, Nginx, Python (elasticsearch client, pandas, matplotlib, seaborn), Flask.
